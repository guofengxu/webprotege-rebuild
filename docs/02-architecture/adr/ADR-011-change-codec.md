# ADR-011 变更编码：`ChangeCodec` 接口，v1 = 每行一条变更的 OWL 函数式语法

- 状态：已接受（带门禁）
- 日期：2026-10-28

## 决策
- 内核定义 `ChangeCodec` 接口，修订表的 `codec` 列记录编码名称和版本，例如 `ofn-lines/1`。
- v1 编码 `ofn-lines/1`：
  - **变更行**（规范形式）：`<op>\t<kind>\t<ontologyKey>\t<ofn>`，按前三个制表符切分，`ofn` 内部可以含制表符；
  - 一个修订编码为 UTF-8 文本，每个物理行一条变更行。写入物理行之前做一层**行转义**：`\` → `\\`、换行 → `\n`、回车 → `\r`；读取时先反转义，再交给函数式语法解析器。这一层转义与函数式语法自身的 `\"`、`\\` 转义互不干扰（先后顺序固定，可逆）；
  - `op` 为 `+` 或 `-`；`kind` 为 `ONTOLOGY`、`AXIOM`、`ANNOTATION` 或 `IMPORT`；
  - `ontologyKey` 是本体在项目内的稳定标识（如 `o1`），匿名本体也有；变更模型里的本体一律用 key 引用，不用 `OWLOntologyID`（后者对匿名本体不稳定）；
  - `kind = ONTOLOGY` 的行登记一个本体：`+\tONTOLOGY\to1\t<本体IRI> <版本IRI>`，匿名时 IRI 写 `-`。它只能出现在创建项目内容的修订里，不可回滚（BS-04）；
  - `ofn` 为 OWL 函数式语法，一律使用完整 IRI，不使用前缀。字面量里的换行原样保留在规范形式中（函数式语法允许字符串内出现换行），由上面的行转义处理；
  - 整个文本用 gzip 压缩后存入 `payload`。
- 迁移包（`interchange-format.md`）中的每条变更是同样的**规范形式**变更行，以 JSON 字符串保存（由 JSON 负责转义，不再叠加行转义），导入时直接复用 `OfnLines.decodeLine`。
- 快照使用另一种编码：`SnapshotCodec`，每个本体一份完整的函数式语法文档，zip 打包（P1-07）。

## 理由
- 与 OWL API 版本无关，可读、可 diff，排查问题时能直接查看。
- 逐条编码保留了变更顺序（BS-01 依赖顺序）。

## 风险与门禁
- 逐行解析比 BinaryOWL 慢。冷启动依靠快照，只重放快照之后的少量修订，所以影响有限。P1-20 测量解码吞吐。
- 匿名个体（blank node）在逐行解析时能否保持同一性，需要在 P1-06 用测试确认并记录结果。如果不能保持，改为“整个修订一份文档”的编码，作为 `ofn-lines/2`。
