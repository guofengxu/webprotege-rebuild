# ADR-005 内存读模型：先用 OWL API 5 自带索引，用基准门禁决定是否自建

- 状态：已接受（带门禁）
- 日期：2026-10-28

## 背景
旧系统在 2019–2020 年用 61 个自建索引类替换了 `OWLOntology`（`index` 目录有 989 次文件变更），主要目的是控制内存。逐个移植这些索引工作量很大，而且旧系统做这件事时用的还是 OWL API 4。

## 决策
- 读模型封装在 `ProjectOntologies` 接口之后，P1 的第一版实现直接用 OWL API 5 的 `OWLOntology`（`OWLManager.createConcurrentOWLOntologyManager()`）及其自带的按实体、按类型查询能力。
- 只有 OWL API 不直接提供的视图才自建：类 / 属性层级（P1-17、P1-18）、显示名称（P1-19）、项目级（跨多个本体）签名。
- P1-20 跑基准测试，门禁阈值见该卡。不达标时新开 ADR，再决定为哪些查询自建索引。

## 理由
- 先用最少的代码打通端到端链路，再按实测数据优化，不凭推测预先优化。
- 接口隔离保证以后替换实现时不影响上层。

## 后果
- 大本体的内存占用可能高于旧系统；基准门禁就是为了尽早暴露这个风险。
