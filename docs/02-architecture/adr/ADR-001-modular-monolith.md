# ADR-001 交付形态：模块化单体（Spring Modulith）

- 状态：已接受
- 日期：2026-10-28

## 背景
上游已把 WebProtégé 拆成微服务（webprotege-next-gen）。本工程由 AI 编码 Agent 为主实现，没有专职运维团队；同时逆向结论表明，“项目”是一致性边界，单个项目的内存本体、层级、短名和写锁必须在同一个进程里。

## 决策
- 采用一个 Spring Boot 应用（`wp-app`）+ 一个纯 Java 内核（`wp-kernel`），应用内用 Spring Modulith 划分模块，模块和允许的依赖见 `overview.md` 第 2 节。
- 用 `ApplicationModules.verify()` 测试守护模块边界，CI 必跑。
- 横向扩展按**项目**分片（同一项目只在一个实例上加载），不按请求分。MVP 只做单实例。

## 理由
- 单进程避免了分布式锁和跨服务一致性问题。
- 对 Agent 来说，模块边界变成可执行的测试，越界会直接让构建失败，比靠文档约束可靠。

## 后果
- 多实例部署需要“项目 → 实例”的路由，留到 P6 以后。
- 需要拆服务时，Modulith 模块就是天然的拆分单元。

## 被否决的选项
- 照搬 next-gen 微服务：运维和集成成本远超当前团队规模，而且同样要解决项目内的单写者问题。
