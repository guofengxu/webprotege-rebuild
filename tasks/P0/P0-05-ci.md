# P0-05 GitHub Actions CI

## 目标
每个 PR 自动运行全量构建与测试，并检查任务索引是否最新。

## 参考
- `tools/plan_lint.py`

## 产出
- `.github/workflows/ci.yml`：在 `push`（main）与 `pull_request` 时触发；`ubuntu-latest`。分成以下 job，只用 GitHub 官方 action（`actions/checkout`、`actions/setup-java`、`actions/setup-python`、`actions/upload-artifact`），改动检测用 shell 中的 `git diff --name-only` 实现，不引入第三方 action：
  - `changes`：输出 `backend`。`actions/checkout` 设置 `fetch-depth: 0`，`pull_request` 时比较 `origin/$GITHUB_BASE_REF...HEAD`，`backend/**`、`pom.xml`、`.mvn/**`、`mvnw*`、`testdata/**`、`docs/api/openapi.json`、`.github/workflows/**` 任一有改动为 true；`git diff` 本身失败时整个 job 失败（不要输出 false 静默跳过）；`push` 到 main 时恒为 true。
  - `plan`（每次都运行；`actions/setup-python` 3.12）：步骤 1 与步骤 1b。
  - `java`（`needs: changes`，`if: needs.changes.outputs.backend == 'true'`；`actions/setup-java` temurin 25，`cache: maven`）：步骤 2。
  - `ci-gate`（`needs` 以上全部，包括 `changes`；`if: always()`）：任一依赖 job 的结果为 `failure` 或 `cancelled` 时失败；`skipped` 视为通过。后续卡片新增的 job（例如 P3-27 的 `frontend`）都加入它的 `needs`。
- 步骤 1：`python tools/plan_lint.py --check --check-index`（卡片不合规，或 `tasks/INDEX.md` / 依赖图与卡片不一致时失败）。
- 步骤 1b（仅 `pull_request`；`actions/checkout` 设置 `fetch-depth: 0`）：用 `.cursor/skills/git-naming-conventions/scripts/validate_names.py` 校验 PR 分支名（`--branch "$GITHUB_HEAD_REF"`），以及 PR 中的每个提交（`--range origin/$GITHUB_BASE_REF..HEAD`）。分支名符合任务卡分支格式（`<type>/pX-NN-...`）时加 `--require-trailers`：每个提交都必须带 `Task:` 与 `Confirmed-by:` 尾注，即经过人工确认（见 `docs/04-dev-workflow.md` 第 ⑥ 步）；其它分支只校验格式。
- 步骤 2：`./mvnw -B verify`。
- 失败时上传 `**/target/surefire-reports/**` 作为构建产物。
- `.github/branch-protection.json`：`required_status_checks` 只写汇总 job（`{"strict": true, "contexts": ["ci-gate"]}`）；合并后由人运行 `python tools/repo_setup.py protect` 生效。

## 实现要点
- 不要用 workflow 级的 `on.pull_request.paths` 过滤：被过滤掉的 workflow 不会上报状态，必需检查会一直等待，PR 无法合并。按端跳过只能在 job 级用 `if:`，由 `ci-gate` 统一上报。
- 本卡的提交要先经人确认、推送并发起 PR，CI 才会第一次运行，所以 CI 结果不作为完成判据，改为合并前的人工检查：人确认本卡 PR 上的 CI 通过；另开一个包含无尾注提交的测试 PR，确认步骤 1b 失败，然后关闭该 PR；这个测试 PR 只改 `tasks/` 下的文件，同时确认 `java` 被跳过而 `ci-gate` 仍有结果。两个运行链接写在本卡 PR 的评论里。
