# P0-05 GitHub Actions CI

## 目标
每个 PR 自动运行全量构建与测试，并检查任务索引是否最新。

## 参考
- `tools/plan_lint.py`

## 产出
- `.github/workflows/ci.yml`：在 `push`（main）与 `pull_request` 时触发；`ubuntu-latest`；`actions/setup-java`（temurin 25，`cache: maven`）；`actions/setup-python`（3.12）。
- 步骤 1：`python tools/plan_lint.py --check --check-index`（卡片不合规，或 `tasks/INDEX.md` / 依赖图与卡片不一致时失败）。
- 步骤 1b（仅 `pull_request`；`actions/checkout` 设置 `fetch-depth: 0`）：用 `.cursor/skills/git-naming-conventions/scripts/validate_names.py` 校验 PR 分支名（`--branch "$GITHUB_HEAD_REF"`），以及 PR 中的每个提交（`--range origin/$GITHUB_BASE_REF..HEAD`）。分支名符合任务卡分支格式（`<type>/pX-NN-...`）时加 `--require-trailers`：每个提交都必须带 `Task:` 与 `Confirmed-by:` 尾注，即经过人工确认（见 `docs/04-dev-workflow.md` 第 ⑥ 步）；其它分支只校验格式。
- 步骤 2：`./mvnw -B verify`。
- 失败时上传 `**/target/surefire-reports/**` 作为构建产物。
- `.github/branch-protection.json`：把 CI 任务名（ci.yml 中的 job 名）写入 `required_status_checks`（`{"strict": true, "contexts": ["<job 名>"]}`）；合并后由人运行 `python tools/repo_setup.py protect` 生效。

## 实现要点
- 本卡的提交要先经人确认、推送并发起 PR，CI 才会第一次运行，所以 CI 结果不作为完成判据，改为合并前的人工检查：人确认本卡 PR 上的 CI 通过；另开一个包含无尾注提交的测试 PR，确认步骤 1b 失败，然后关闭该 PR。两个运行链接写在本卡 PR 的评论里。

## ECC 技能
工作项类型：`ci-devops` —— CI、Docker Compose 与部署配置。规则见 `.cursor/skills/wp-ecc-routing/SKILL.md`，也可以运行 `python tools/task.py ecc P0-05` 查看。

- 开工前加载的 skill：`deployment-patterns`、`docker-patterns`、`github-ops`
- 提交前调用的审查 agent：`code-reviewer`
- 提交信息：skill `conventional-commit-review`（或 agent `commit-reviewer`）起草，由 `tools/task.py finish` 校验；不写尾注，提交由人运行 `tools/task.py commit` 确认

```bash
python tools/plan_lint.py --check
```
